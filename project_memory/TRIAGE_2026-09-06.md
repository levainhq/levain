`_spawn_shell_impl`. Not new work; it is corroboration of work already queued.

**LOW `tools.py:202` — CONFIRMED, AND IT REINTRODUCES THIS RELEASE'S OWN HEADLINE CLASS.**
In `_close_candidate_shell`, the base teardown is reached only by falling off the end of the
`except BaseException: _log.exception(...)` that handles a raising `candidate.close()`. If that
logging call ITSELF raises — a custom handler whose `emit` raises without calling `handleError` —
the function exits before `SandboxedShell.close(candidate)` and the rejected shell leaks. That is
precisely what `bdb4b2f` was written to make impossible ("THE BASE TEARDOWN RUNS UNCONDITIONALLY"),
reintroduced one layer up through the logging call rather than the `return` that was removed.
▶ ~5 lines: run the base teardown from a `finally`, and guard each log call separately.
⚠ NOT fixed today on purpose — the fix lands inside round 10's reviewed span, and editing the tree
after the clearing verdict is what the pre-registration method exists to prevent.

**LOW `tools.py:578` — CONFIRMED, narrow, PARKED.** A `KeyboardInterrupt` in the window between

unset and never closes the subprocess/FIFO/reader thread. codex's own remedy is an
ownership-transfer redesign (context manager / unstarted-shell protocol) — a design change, not a
hardening, and not on a release's critical path.
