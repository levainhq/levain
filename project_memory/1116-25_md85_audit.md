# levain#85 audit: cockpit surfaces that show an agent's reply

The one renderer is `renderMarkdown` (dashboard_core.js / markdown.js, parity-locked). Surfaces that show an agent's untrusted text go
through `LevainRoomView.drawMarkdown` (room_view.js), which calls that renderer, filters links to http(s)/mailto off the cockpit's own
host, bounds the size, and falls back to plain text. No second renderer was added.

Notes
- A Desk event that is not the desk's own reply stays plain text. The voice (Premium TTS and on-device) reads the event's
  `text` (voiceReply), not the DOM; a test pins that the tracker receives the reply as written.
- Desk hidden-character marks (`shown()`) are applied before the renderer, so they still appear as text.
- The chat panel mounts on `nav.tabs`, which the shipped dashboard.html does not carry, so the panel is dormant on the current page.
  The change is in place and its test supplies the strip.
- The existing desk test that read a reply's second innerText line now ignores blank lines (a paragraph adds one).

Residue (Phill's look): how the drawn reply reads on the Desk, thread, chat and Sessions surfaces at phone and desktop widths. Measured here
is structure only (elements present, no marker characters), not appearance.
